|---|---|
| **เรื่องที่แก้ไข** | เพิ่มหน้า Nuxt สำหรับจัดการ QCItem ที่ `/csm-next/master/qc-item/` แทนการทำงานของหน้า legacy โดยคง backend contract เดิม |

## รายการ Test Case

### TC-01: เปิดหน้าและแสดงรายการ QCItem พร้อม pagination

| รายการ | รายละเอียด |
|---|---|
| **ประเภท** | Happy path |

| **ข้อมูลทดสอบ (Test Data)** | รายการ QCItem อย่างน้อย 11 รายการ เช่น `itemno=1..11`, Description และ Remark ไม่ว่าง |

**ขั้นตอนการทดสอบ (Test Steps):**

  - _ผลลัพธ์ที่คาดหวัง:_ ตารางมีคอลัมน์ `No.`, `Action`, `Description`, `Remark`, `Add date` และข้อมูลหน้าแรกไม่เกิน 10 แถว

### TC-02: เพิ่ม แก้ไข ลบ และบันทึกรายการ QCItem

| รายการ | รายละเอียด |
|---|---|
| **ประเภท** | Happy path |
| **เงื่อนไขเริ่มต้น (Pre-condition)** | อยู่หน้า QCItem และมีข้อมูลเดิมอย่างน้อย 1 รายการ |
| **ข้อมูลทดสอบ (Test Data)** | Description ใหม่ `ความสะอาดพื้นที่`, Remark ใหม่ `ตรวจทุกสิ้นวัน` |

**ขั้นตอนการทดสอบ (Test Steps):**

- [ ] **1.** กดปุ่ม `เพิ่มรายการ`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบเพิ่มแถวใหม่ท้ายชุดข้อมูล เลข `itemno` ถัดจากเลขสูงสุด และช่อง Description/Remark ว่างเพื่อแก้ไขทันที
- [ ] **2.** กรอก Description = `ความสะอาดพื้นที่` และ Remark = `ตรวจทุกสิ้นวัน` ในแถวใหม่
  - _ผลลัพธ์ที่คาดหวัง:_ ค่าที่กรอกแสดงอยู่ในช่องตารางโดยไม่ต้องเปิดหน้าแก้ไขแยก
- [ ] **3.** เลือกแถวเดิมที่มีข้อมูลแล้วกดปุ่มลบ และยืนยันการลบ
  - _ผลลัพธ์ที่คาดหวัง:_ แถวถูกนำออกจากรายการบนหน้าจอ และยังไม่มี request บันทึกจนกว่าจะกด `บันทึก`
- [ ] **4.** กดปุ่ม `บันทึก`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบบันทึกรายการทั้งชุดผ่าน `QCItem_Create`, แสดงข้อความบันทึกสำเร็จ และโหลดรายการล่าสุดกลับมา
- [ ] **5.** refresh หน้าแล้วตรวจสอบรายการ
  - _ผลลัพธ์ที่คาดหวัง:_ รายการที่เพิ่ม/แก้ไขยังอยู่ และรายการที่ลบไม่กลับมา โดยเลขลำดับเป็นไปตามข้อมูลจาก backend

  - _ผลลัพธ์ที่คาดหวัง:_ ระบบไม่ส่ง `QCItem_Create` และแสดงข้อความแจ้งให้กรอก Remark พร้อมเลขรายการที่มีปัญหา

### TC-04: นำเข้าไฟล์ QCItem ด้วย `.xlsx`

| รายการ | รายละเอียด |
|---|---|
| **ประเภท** | Happy path / Negative |
| **เงื่อนไขเริ่มต้น (Pre-condition)** | Login สำเร็จและมีไฟล์ Excel ที่มีหัวตาราง/ข้อมูล `itemno`, `itemname`, `remark` |
| **ข้อมูลทดสอบ (Test Data)** | `QCItem.xlsx` ที่มีแถว `1, ความสะอาดพื้นที่, ตรวจทุกสิ้นวัน` และไฟล์ผิดประเภท `QCItem.pdf` |

**ขั้นตอนการทดสอบ (Test Steps):**

- [ ] **1.** กด `นำเข้า Excel` แล้วเลือกไฟล์ `QCItem.xlsx`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบเปิด dialog นำเข้าและแสดงชื่อไฟล์ที่เลือก โดยยังไม่ upload ทันที
- [ ] **2.** กด `อัปโหลด`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบส่งไฟล์ด้วย field ชื่อ `file` ไปยัง `QCItem_Import`, ปุ่มอัปโหลดถูก disable ระหว่างดำเนินการ และเมื่อสำเร็จ dialog ปิดพร้อมโหลดรายการใหม่
- [ ] **3.** เลือกไฟล์ `QCItem.pdf`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบไม่ส่ง upload และแสดงข้อความให้เลือกไฟล์ `.xlsx` เท่านั้น
- [ ] **4.** ใช้ไฟล์ `.xlsx` ที่ backend ปฏิเสธ แล้วกด `อัปโหลด`
  - _ผลลัพธ์ที่คาดหวัง:_ dialog ยังคงเปิดอยู่และแสดงข้อความ error จาก backend เพื่อให้เลือกยกเลิกหรือลองใหม่ได้

### TC-05: ส่งออก Excel และนำไฟล์กลับเข้าเป็น round trip

| รายการ | รายละเอียด |
|---|---|
| **ประเภท** | Happy path / Regression |
| **เงื่อนไขเริ่มต้น (Pre-condition)** | Login สำเร็จและมีข้อมูล QCItem; backend สามารถสร้าง export token ได้ |
| **ข้อมูลทดสอบ (Test Data)** | ข้อมูล QCItem ปัจจุบัน และไฟล์ที่ได้จากปุ่ม `ส่งออก Excel` |

**ขั้นตอนการทดสอบ (Test Steps):**

- [ ] **1.** กดปุ่ม `ส่งออก Excel`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบเรียก `QCItem_ExportExcel` แล้วเปิด download URL ผ่าน `Api/File/DownLoad?download=true&id=...` โดยใช้ token จาก server
- [ ] **2.** ตรวจสอบไฟล์ที่ดาวน์โหลด
  - _ผลลัพธ์ที่คาดหวัง:_ ไฟล์เป็น `.xlsx`, เปิดได้, มีชื่อไฟล์จาก server และข้อมูล/คอลัมน์ไม่เสียหาย
- [ ] **3.** นำไฟล์ที่ได้กลับเข้าผ่าน `นำเข้า Excel`
  - _ผลลัพธ์ที่คาดหวัง:_ backend รับไฟล์ได้และรายการบนหน้าจอถูก refresh โดยข้อมูลหลักของ QCItem ยังคงตรงกับไฟล์

### TC-06: Authentication และสถานะ loading/error/empty

| รายการ | รายละเอียด |
|---|---|
| **ประเภท** | Regression |
| **เงื่อนไขเริ่มต้น (Pre-condition)** | ทดสอบทั้งกรณีมี session, ไม่มี session, API error และบริษัทไม่มีข้อมูล |
| **ข้อมูลทดสอบ (Test Data)** | session ที่หมดอายุ/ไม่มี token, response HTTP 401, response HTTP 403, และ raw list `[]` |

**ขั้นตอนการทดสอบ (Test Steps):**

- [ ] **1.** เปิด route โดยไม่มี internal session
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบแสดงสถานะต้องเข้าสู่ระบบและ redirect ไป login โดยไม่เรียก `QCItem_ReadList`
- [ ] **2.** เปิด route ด้วย session ที่ใช้ได้ ขณะจำลอง API กำลังตอบกลับ
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบแสดง loading state และปุ่ม/การกระทำของหน้าจอไม่ทำให้เกิด request ซ้ำโดยไม่จำเป็น
- [ ] **3.** จำลอง `QCItem_ReadList` ตอบ HTTP 401 แล้วเปิดหน้าใหม่
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบจัดการเป็น session หมดอายุและไม่แสดงเป็น empty list
- [ ] **4.** จำลอง `QCItem_ReadList` ตอบ HTTP 403
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบแสดง error/permission state โดยไม่ล้าง session อัตโนมัติ
- [ ] **5.** จำลอง `QCItem_ReadList` ตอบ raw array ว่าง `[]`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบแสดง empty state พร้อมปุ่ม `เพิ่มรายการ` ให้เริ่มสร้างข้อมูลได้
- [ ] **6.** จำลอง `QCItem_ReadList` ตอบ HTTP 200 แต่ body ไม่ใช่ raw array เช่น `{}` แล้วตรวจสอบปุ่ม `บันทึก`
  - _ผลลัพธ์ที่คาดหวัง:_ ระบบแสดง invalid-response/error state ไม่แสดงเป็น empty list และปุ่ม `บันทึก` ถูก disable เพื่อป้องกันการส่งชุดข้อมูลว่างไปแทนที่ข้อมูลเดิม
- [ ] **7.** เริ่ม request `บันทึก` หรือ `อัปโหลด` แล้วลองแก้ไข/เพิ่ม/ลบรายการระหว่างรอผล
  - _ผลลัพธ์ที่คาดหวัง:_ controls สำหรับแก้ไขชุดข้อมูลถูก disable จนกว่า request และ reload จะเสร็จ เพื่อไม่ให้ local edits ถูกทับโดย response เก่า
- [ ] **8.** ทดสอบหน้าจอที่ความกว้างประมาณ 390px
  - _ผลลัพธ์ที่คาดหวัง:_ action buttons จัดเรียงอ่านได้ ตารางเลื่อนได้ในแนวนอน และไม่มีข้อมูล/ปุ่มถูกตัดจนใช้งานไม่ได้

## หมายเหตุสำหรับ QA/UAT

- การทดสอบนี้เป็น frontend target route ที่ path `Nuxt/app/pages/master/qc-item/index.vue`; route legacy `/page/Master/v_csm_mas_011/` ไม่ได้ถูกลบหรือเปลี่ยนแปลง
- ต้องทดสอบกับ backend จริงเพื่อยืนยันสิทธิ์บริษัท, persistence, ชื่อไฟล์/bytes ของ export และพฤติกรรม import ข้ามบริษัท
- Source backend ปัจจุบันมีความเสี่ยงใน `QCItem_Import` ที่ lookup ด้วย `itemno` โดยไม่รวม `maincode`; ให้ทำ TC เพิ่มใน UAT กับสองบริษัทที่มี `itemno` เดียวกัน และอย่าปิด Issue #22 จนกว่าผู้รับผิดชอบ backend จะยืนยันผล
